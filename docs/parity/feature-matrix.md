# Feature parity matrix

The tracking source of truth for capability parity across evt implementations (plan decision D7,
policy in [ADR 0006](../adr/0006-parity-policy-and-feature-cuts.md)). When a capability changes,
its row changes in the same PR — review rejects capability changes that leave this matrix stale.

**Upkeep (D7).** One row per capability. Every evt PR that adds, changes, ports, defers, or cuts a
capability updates its row (status, tier, or a new row). Plan IDs (`C1`, `X1`, `P1`, `F1`, `K1`,
…) are stable and shared with the plan, issues, and PR titles; existing features carry `B` ids.
The `Go`/`Rust`/`TS` cells reflect the code on the default branch, not aspiration. The `Issue`
column links the tracking issue when one exists.

**Legend.** ✅ shipped · 🚧 in progress · ⏳ planned · ⏸ deferred (Go-only; ported on first
consumer) · ✂️ cut/deprecated · — not applicable.
