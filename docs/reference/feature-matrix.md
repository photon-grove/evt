# Feature parity matrix

This table tracks which capabilities each evt implementation has. The policy behind it is in
[ADR 0006](../adr/0006-parity-policy-and-feature-cuts.md). Each capability gets one row, and a PR
that adds, changes, ports, defers or cuts a capability updates its row in the same PR, so the
`Go`, `Rust` and `TS` cells describe the code on the default branch rather than plans. The `Issue`
column links the tracking issue when there is one.

Rows are grouped roughly by when the capability arrived: the original Go feature set first, then
the core reshape in [ADR 0004](../adr/0004-core-reshape-multi-stream-transactions-and-outcomes.md),
the Rust-first extensions in [ADR 0005](../adr/0005-rust-first-extensions-journal-and-lambda.md),
the Rust ports and follow-ups, the deferred features, and last the features that were cut.

Status: ✅ shipped, 🚧 in progress, ⏳ planned, ⏸ deferred (single-language, ported for its first
consumer), 🗑️ cut and removed, and — for not applicable.
